## 1. 研究定位与不可违反的边界

本项目属于**基于真实事件材料构建场景的探索性多智能体反事实仿真**。以下边界适用于本文全部结论：

1. 仿真轮次中的"小时"不等于经过现实校准的小时（1 轮 = 60 模拟分钟，是模型配置值）。
2. 仿真结果**不代表**现实政策效果的精确因果估计，只用于在给定假设下比较不同干预条件的相对差异。
3. 微博真实数据（官方辟谣帖及其评论）仅用于**场景构建、公众反应参考与有限的合理性检查**，不能直接当作原谣言的传播曲线。
4. 仿真中的每个体行为由 LLM 生成，Agent 并非真实人群抽样，因此传播规模量级不具外部效度。
5. 未经跨轮次对齐校准的模型参数（活跃度、时间尺度）是**建模假设**，已在本文中显式列出。

## 2. 技术栈与运行环境

| 组件 | 版本 / 取值 | 说明 |
|---|---|---|
| MiroFish 上游仓库 | Commit `7657031` | https://github.com/666ghj/MiroFish |
| 底层 simulator | `camel-oasis 0.2.5` / `camel-ai 0.2.78` | OASIS 双平台（Twitter + Reddit） |
| 图谱与记忆 | Zep Cloud（`zep-cloud 3.25.0`） | Agent 记忆与实体关系存储 |
| LLM | `deepseek-chat`（DeepSeek 官方，OpenAI 兼容接口） | 全部 Agent 决策由该模型生成 |
| Python | 3.12（uv 管理的 venv） | 后端 Flask，端口 5001 |
| 时间尺度 | `minutes_per_round = 60` | **实测自 `simulation_config.json`**，非假设值 |
| 随机种子 | 每轮 Python 侧固定（`random_seed`） | LLM 采样本身不可复现 → 必须靠重复实验 |

**本工程对上游的两处受控修改**（补丁脚本 `mirofish/scripts/apply_runner_patch.py`，补丁前后文件均已入库 `mirofish/patches/`）：

1. **补齐 `event_config.scheduled_events`**：上游 `simulation_config_generator.py` 将该字段恒置为 `[]`，且运行器内无任何消费逻辑（已全仓检索验证）。本补丁在指定轮次进入 Agent 自主动作**之前**，向选定 Agent 注入一次 `CREATE_POST`，使"政府于模拟第 k 小时辟谣"成为可执行、可在日志中核验的真实干预。
2. **`random_seed` 生效**：使 Agent 激活抽样在 Python 侧可复现。

二者的共同点是：**不改变 Agent 的自主决策逻辑**，只改变研究者可控的注入与抽样部分。

## 3. 技术验收（正式实验前的必要条件，逐条实测）

| 验收项 | 方法 | 结果 |
|---|---|---|
| ① Agent 是否真实活跃 | 检查 `active_hours`、`activity_level` 与 `run_parallel_simulation.py:1071` 的激活判定 | ✅ 已修复：原 LLM 生成的 `active_hours` 仅限工作时段而仿真自 hour 0 起始，导致零自主动作（旧运行整轮 0.1 秒）。现统一覆写为全时段 + `activity_level=0.9`，每轮激活 6–8 个 Agent |
| ② 是否形成真实传播互动 | 检查 `actions.jsonl` 中的 `CREATE_COMMENT / LIKE_POST / DISLIKE_POST / LIKE_COMMENT / REPOST` | ✅ 评论、点赞、点踩均已观测；⚠️ **REPOST 计数为 0**（Twitter 提供该动作但 Agent 未选择，Reddit 无原生转发）→ 不把发帖量称为"传播规模" |
| ③ 初始状态可控 | 覆写 `event_config.initial_posts`，移除 LLM 自定义初帖 | ✅ 初帖被严格替换为研究者设定的 4 条谣言帖，避免官方辟谣提前泄露。⚠️ 图谱自带的公安/辟谣类 Agent 仍可能**自主**发辟谣内容，属允许行为，已在结论中说明 |
| ④ 干预真正生效 | 运行后置核验：按干预文本唯一标记串检索 `actions.jsonl`，检查首次出现的 `round` | ✅ 4 轮小测显示干预精确落在第 1 轮，并在后续轮次被其他 Agent 引用与扩散 |
| ⑤ 指标可正确解析 | 以 `actions.jsonl` 的 `round_start/round_end` 还原完整轮次 | ✅ 已修正"实际 2 轮却只解析出 1 轮"的缺陷（旧版用 `timeline`，会漏空轮） |

## 4. 三组实验设计

所有实验条件共用**同一批 Agent、同一张社交网络、同一份 Seed、同一时间尺度与同一活跃度参数**，并采用**同一个已 prepare 的 simulation**（`run_formal_experiments.py` 在每组运行前先 `stop + close-env` 并删除上一组的数据库与动作日志，防止组间污染）。

### 实验一：谣言形式对传播的影响

| 条件 | 刺激 | 干预 |
|---|---|---|
| E1A | 传统文字谣言 4 条 | 无（同时作为实验二、三的共同基线） |
| E1B | AIGC 高拟真图文谣言 4 条 | 无 |

**重要限定**：MiroFish 当前版本**不支持**向 Agent 呈现真实图片或视频。因此 E1B 是**以高拟真视觉描述文本为刺激的文本代理实验**（text-proxy），论文中不得称为真实多模态 AIGC 图像刺激实验。该限制写入论文的局限部分。

### 实验二：政府辟谣介入时点

| 条件 | 干预内容 | 注入轮次（≈模拟小时） |
|---|---|---|
| E2R1 | 传统公文式辟谣（改写自 P1-01 通报原文） | 第 1 轮 |
| E2R4 | 同上 | 第 4 轮 |
| E2R12 | 同上 | 第 12 轮 |

基线统一复用 **E1A**（同 seeds、同网络、同轮数），并在论文中明示该对应关系，不把不同配置的结果拼接。

### 实验三：政府辟谣回应形态

| 条件 | 干预内容 | 注入轮次 |
|---|---|---|
| E2R4（≡ E3A） | 传统公文式辟谣 | 第 4 轮 |
| E3B | 数智实证型辟谣 = 定性结论 + 客观灾情数据 + AI 造假识别要点 + 民生保供信息 + 核验渠道 | 第 4 轮 |

**重要限定**：E3A 与 E3B 两组在文本长度、证据数量、内容结构与呈现方式上**同时存在差异**，因此只能得出"两种综合回应策略之间的条件性差异"，**不能声称识别了某一单一因素（如"是否附数据"）的因果效果**。

### 规模、轮次、平台与重复

- Agent 数：8（由 Zep 图谱实体数 × 0.9 自动推导，不可手填；见第 8 节局限）
- 轮数：16（= 960 模拟分钟），保证第 12 小时干预后仍有 4 轮观察窗口
- **运行平台：Reddit 单平台**（`platform = "reddit"`）。决策理由（经实测，非偏好）：
  1. OASIS 的 Twitter 通道在推荐排序环节依赖 HuggingFace 上的 `Twitter/twhin-bert-base`，
     本机对该域名的直连不稳定（SSL EOF + 5 次重试后失败），会导致多轮运行卡死甚至进程退出；
  2. 预实验实测：Twitter 侧只产生发帖，**评论 / 点赞 / 点踩全部发生在 Reddit 侧**，
     `REPOST` 在两组中均为 0，因此 Twitter 对本文关心的互动指标贡献为零；
  3. Reddit 单平台还可把每组运行的时间与费用降低约一半，用于在预算内增加重复次数。
  → 该选择会在论文的局限中明确写出："以 Reddit 讨论类平台作为仿真场景，不做跨平台外推"。
- 重复：每个条件计划 3 次独立重复（不同 `random_seed`）。**若实际完成 < 3 次，不使用"显著""稳定"等统计性结论措辞**。

## 6. 评价指标与计算方法

全部指标由 `mirofish/scripts/analyze_formal_results.py` 从原始 `actions.jsonl` 计算，公式与口径如下：

| 指标 | 定义 | 口径说明 |
|---|---|---|
| 逐轮互动量 | `CREATE_POST + CREATE_COMMENT + REPOST + QUOTE_POST + LIKE/Dislike(POST/COMMENT)` | 排除 `DO_NOTHING / REFRESH / SEARCH_* / TREND / MUTE` |
| 谣言相关互动量 | 谣言类内容数 + **指向谣言内容的互动数** | 关键：利用 `LIKE_POST` 等动作的 `post_content` 字段判断互动对象立场，而非只看总量 |
| 辟谣相关互动量 | 辟谣/求证类内容数 + 指向辟谣内容的互动数 | 同上；注入帖用唯一标记串精确识别 |
| 内容立场分类 | 关键词启发式规则（判辟谣优先，再判谣言，其余中性） | 局限：无法识别反讽与引用式否定；结果仅供探索性描述，样例随结果一并留存于 `content_stance_summary.json` |
| 参与广度 | 产出某类内容的去重 Agent 数 | |
| 峰值 / 达峰轮次 | `argmax(逐轮谣言相关互动量)` 及其轮次 | |
| 干预后窗口指标 | 注入轮次及其之后的累计/均值 | 用于比较"介入后传播是否被抑制" |

**明确不予量化的指标**（无对应可核验字段，仅作定性讨论或局限）：
恐慌强度、囤货率、政府信任度、二级传播深度（传播树不可重建：`CREATE_COMMENT.action_args` 不含被评论对象；`REPOST` 计数为 0）。

## 7. 可复现执行流程

```bash
# 1) 启动后端
cd Desktop/MiroFish/backend && uv run python run.py        # Flask 127.0.0.1:5001

# 2) 打补丁（幂等，仅需一次；MiroFish 重装后需重打）
python mirofish/scripts/apply_runner_patch.py

# 3) 运行全部正式实验条件（含重复）
python mirofish/scripts/run_formal_experiments.py \
    --rounds 16 --simulation-id <sim_id> \
    --out-root mirofish/results/formal_20261021 \
    --plan mirofish/results/plan_formal_20261021.json

# 4) 汇总指标
python mirofish/scripts/analyze_formal_results.py mirofish/results/formal_20261021

# 5) 出图（PDF 矢量 + 300 DPI PNG）
python mirofish/scripts/plot_formal_figures.py mirofish/results/formal_20261021
```

原始运行记录（含大体积 `*.jsonl` 与 SQLite 数据库）保留在本地
`Desktop\MiroFish\backend\uploads\simulations\<sim_id>\`，
仓库内保存每个条件的快照副本（`simulation_config.json`、`simulation.log`、`*_actions.jsonl`）。

## 8. 已知局限（将在论文第四章中明示）

1. **Agent 规模偏小**：8 个 Agent 由图谱实体数决定，无法直接指定。因此传播量级与扩散形态不具外部效度，只用于组间相对比较。
2. **缺少转发链**：无法重建级联传播树，无法计算传播深度、二级传播率等网络指标。
3. **内容立场依赖关键词规则**：可能误判反讽、否定引用等表达。
4. **干预注入为二次开发的运行时补丁**：注入时机与内容严格受控并可核验，但属于对上游代码的定制修改。
5. **LLM 采样不可复现**：即使固定随机种子，模型输出仍有随机性，因此结论依赖重复运行的离散程度，不能以单次运行下结论。
7. **仅单一社交平台**：只运行 Reddit，Twitter 侧的跨平台外推不成立（原因见第 4 节）。
8. **现实对照有限**：真实侧数据主要是官方辟谣帖评论，无法直接与原谣言传播曲线对齐，因此只做趋势形态层面的合理性检查。
