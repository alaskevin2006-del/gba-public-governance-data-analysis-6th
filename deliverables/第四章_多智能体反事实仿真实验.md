## 4.1 研究目标与反事实仿真定位

第三章的实证分析揭示了涉灾 AIGC 谣言的生成套路、传播特征与官方治理的基本形态，但其数据基础是**事后留痕**（官方通报、平台处置、公开评论），存在两个无法由观测数据弥补的缺口：

1. 观测不到"如果政府晚介入几小时会怎样"——真实事件只有一条已实现的时间路径；
2. 观测不到"如果换成另一种回应形态会怎样"——真实事件只采用过一种回应文本。

本章的目标是**用受控的多智能体仿真补上这两类反事实对照**，回答三个问题：

- **问题一（形式）**：在相同初始条件下，以高拟真视觉描述为特征的 AIGC 谣言，是否比传统文字谣言引发更强的传播反应？
- **问题二（时点）**：在同一版辟谣内容下，第 1、4、12 模拟小时介入的传播后果有何差异？
- **问题三（形态）**：在相同介入时点下，传统公文式辟谣与"数智实证型"辟谣的传播后果有何差异？

**本章研究的定位必须前置说明**：这是一项**基于真实事件材料构建场景的探索性反事实仿真**。仿真中的 Agent 不是真实人群抽样，每个体的行为由大语言模型（LLM）生成；仿真的"小时"是模型时间单位，**不等于经过现实校准的现实小时**；现有微博数据仅够用于场景构建与有限的形式合理性检查，不足以校准传播速率参数。因此本章的全部比较都是**在同一套模型假设下的条件性比较**，不能被解释为现实政策效果的因果估计。

## 4.2 MiroFish 技术架构与使用方式

本研究采用 MiroFish（上游 Commit `7657031`）作为仿真平台，其底座为 CAMEL-AI 的 OASIS 双平台社交模拟器，并接入 Zep Cloud 作为实体记忆与图谱存储。

| 组件 | 版本 / 取值 |
|---|---|
| MiroFish 上游 | Commit `7657031` |
| 模拟器 | `camel-oasis 0.2.5` / `camel-ai 0.2.78` |
| 图谱与记忆 | Zep Cloud（`zep-cloud 3.25.0`） |
| 决策模型 | `deepseek-chat`（OpenAI 兼容接口） |
| 运行环境 | Python 3.12（uv 管理的虚拟环境），Flask 后端 :5001 |
| 时间尺度 | `minutes_per_round = 60`（实测自 `simulation_config.json`，非假设值） |

**运行链路**：种子材料 → 本体抽取（LLM） → Zep 知识图谱 → Agent 画像与配置生成 → 双平台（Twitter / Reddit）环境初始化 → 逐轮推进（每轮抽取若干被激活的 Agent，由 LLM 决定其动作） → 动作日志（`actions.jsonl`）与平台数据库落盘。

### 4.2.1 对上游的两处受控修改

上游版本存在两处使本研究无法按设计执行的问题，本工程以补丁形式做了最小必要修改（补丁脚本 `mirofish/scripts/apply_runner_patch.py`，补丁前后文件均已入库以便审计）：

1. **补齐定时事件字段**：上游 `simulation_config_generator.py` 将 `event_config.scheduled_events` 恒置为 `[]`，且运行器中不存在任何消费该字段的代码（已全仓检索确认）。若不处理，"第 k 小时介入"这一核心实验条件**无法实现**。补丁在指定轮次进入 Agent 自主动作之前，向指定 Agent 注入一条发帖动作；注入的轮次、内容、发布者均写入配置并在运行日志中留痕。
2. **随机数种子生效**：补丁使配置项 `random_seed` 传递给 `random.seed()`，令 Agent 激活抽样在 Python 侧可复现。

两者都**不修改 Agent 的自主决策逻辑**，只改变研究者可控的部分。

### 4.2.2 关于运行平台的说明

OASIS 的 Twitter 通道在推荐排序环节依赖 HuggingFace 上的在线模型 `Twitter/twhin-bert-base`。在本次实验环境中，对该域名的直连不稳定，会在若干轮后出现连接失败、重试耗尽直至进程崩溃；同时，预实验实测发现 Twitter 侧**只产生发帖行为**，评论、点赞、点踩等本研究关心的互动几乎全部发生在 Reddit 侧，且 `REPOST`（转发）在两组中均无人使用。

因此本研究**统一以 Reddit 讨论类平台作为仿真场景**。这一选择使每组运行的时间与调用开销约减半，从而在预算内获得更多次独立重复。代价是：结论不做跨平台外推，Twitter 侧的转发级联行为不在本章观测范围内。

### 4.3.2 Agent 画像的生成与 Agent 数量

Agent 由 Zep 图谱实体转换而来：**Agent 数量 = 图谱实体数 × 0.9**（由上游 `_generate_time_config` 计算，不可由研究者直接指定）。本次制备得到 **8 个 Agent**，涵盖：

| 类型 | 实例（由 LLM 依真实材料生成） |
|---|---|
| Person（个人） | 温州本地自媒体运营者陈航、AI 造假者高某某 |
| RumorForwarder | 中小资讯类自媒体工作室 |
| GovernmentAgency / Organization | 上海公安机关、浦东警方、宁波/温州公安机关 |
| 官方辟谣平台 | 中国互联网联合辟谣平台 |

每个 Agent 都带有由 LLM 依据真实材料生成的人物设定（身份背景、发言风格、立场、事件记忆），这是当前 LLM 驱动的 Agent 仿真研究的通行做法，也是本研究"现实合理性"的主要来源。

**必须承认的局限**：8 个 Agent 且机构类占比偏高（5/8）。因此本实验只能观察"小群体讨论内的相对差异"，传播规模量级不具外部效度；公众视角的行为由少量个人 Agent 承担，这是本章数据薄弱之处。曾尝试通过扩充种子提升实体抽取数量，但受限于实体抽取稳定性与时间成本，本次未增大规模，作为改进方向写入 4.11。

## 4.4 网络、行为规则与时间参数

| 参数 | 取值 | 说明与理由 |
|---|---|---|
| `minutes_per_round` | 60 | 实测自配置文件；故第 k 轮 ≈ 模拟第 k 小时 |
| 总观察轮数 | 16 | 保证第 12 小时介入后仍有 4 轮观察窗口 |
| `activity_level` | 0.9 | 覆写值（原生成值偏低且仅工作时段活跃） |
| `active_hours` | 全 24 小时 | 覆写值。原值使仿真自 hour 0 起零自主动作（见 4.5） |
| 每轮激活 Agent 数 | 6–8（视该轮活跃度） | 覆写为固定区间，避免早晚 $\times$ 0.05 的峰谷衰减 |
| `agents_per_hour_min/max` | 6 / 8 | 同上 |
| `random_seed` | 每次运行不同（如 20261022、20261023…） | 仅保证 Python 侧抽样可复现；LLM 采样本身不可复现 |
| 社交网络结构 | 由 OASIS 依据平台默认规则生成（初始无预置关注关系） | 关注/屏蔽关系在仿真中由 Agent 自主形成（FOLLOW/MUTE） |

**上述活跃度覆写参数是建模假设，不是现实标定结果。** 其作用是让传播过程在有限轮次内可被观测；由于所有实验条件使用完全相同的活跃度参数，组间差异仍可归因于目标变量。

## 4.5 模型假设与技术有效性检查

正式实验前做了五项必验收，逐条实测：

1. **Agent 是否真实活跃**：初始运行中，LLM 生成的 `active_hours` 被限定在工作时段（如 [9,10,11,14,15,16]），而仿真自 hour 0 起始，激活判定 `if current_hour not in active_hours: continue` 使所有自主动作被跳过——表现为整轮循环 0.1 秒完成、动作全部来自预置初帖。修复后，Agent 在每一轮都可能被调用。
2. **是否形成真实传播互动**：修复后评论（`CREATE_COMMENT`）、点赞（`LIKE_POST` / `LIKE_COMMENT`）、点踩（`DISLIKE_POST`）均已稳定出现，多个 Agent 参与；**转发 `REPOST` 始终为 0**，因此本章不把发帖量称为"传播规模"。
3. **初始状态是否可控**：`event_config.initial_posts` 被研究者严格替换为目标谣言文本，剔除 LLM 自行生成的初始帖（含可能提前泄露官方辟谣的帖子），每次运行记录被剔除的条数。需注意：图谱自带的公安、辟谣平台类 Agent 仍可能**自主**发布辟谣性质内容，这属于被允许的自主行为，因此在结果解读中，"无官方干预"是指**研究者未注入任何官方辟谣事件**，而非"环境中不存在官方声音"。
4. **干预是否真正生效**：每次运行结束后，以干预文本的唯一标记串检索 `actions.jsonl`，核验其首次出现的轮次是否与设定一致。正式实验结果中的 `intervention_verify` 字段逐条记录了该项核验。
5. **指标能否正确解析**：改用 `actions.jsonl` 中的 `round_start` / `round_end` 标记还原完整轮次序列（原先用 `timeline` 接口会漏掉无动作的轮次，导致"实际 16 轮只解析出少数几轮"的错误）。

## 4.6 三组实验设计与控制变量

三组实验**共用同一批 Agent、同一张初始网络、同一份种子材料、同一套时间参数与活跃度配置**，并复用同一个已完成画像制备的仿真实例；每完成一组，先停止并关闭环境、删除上一组的数据库与动作日志，再开始下一组，以防止组间状态污染。

### 实验一：谣言形式

| 条件 | 刺激内容 | 干预 |
|---|---|---|
| E1A | 传统文字谣言 4 条 | 无（同时作为实验二、三的共同基线） |
| E1B | AIGC 高拟真图文谣言 4 条 | 无 |

**重要限定**：MiroFish 当前版本不支持向 Agent 呈现真实图片或视频帧。因此 E1B 是**以"高拟真视觉描述"为刺激的文本代理实验（text-proxy）**，而非真实多模态刺激实验。它可以检验"当谣言文本携带更强的现场感与画面描述时传播是否更强"，但**不能**等价于真实 AIGC 图片的视觉说服力。

### 实验二：辟谣介入时点

| 条件 | 干预内容 | 注入轮次（≈模拟小时） |
|---|---|---|
| E2R1 | 传统公文式辟谣 | 第 1 轮 |
| E2R4 | 传统公文式辟谣 | 第 4 轮 |
| E2R12 | 传统公文式辟谣 | 第 12 轮 |

三者使用**完全相同的**辟谣文本（改写自真实通报 P1-01，未添加新事实），唯一差别是注入时刻；基线统一复用 E1A。

### 实验三：辟谣回应形态

| 条件 | 干预内容 | 注入轮次 |
|---|---|---|
| E2R4（≡ E3A） | 传统公文式辟谣：定性结论 + 处罚结果 + 警方提示 | 第 4 轮 |
| E3B | 数智实证型辟谣：定性结论 + 客观灾情数据 + AI 造假识别要点 + 民生保供信息 + 核验渠道 | 第 4 轮 |

**重要限定**：两组在文本长度、证据条目数、表达方式与呈现结构上**同时存在差异**，因此只能陈述"两种综合回应策略之间的条件性差异"，不能声称识别了单一因素（例如"是否附数据"）的因果效应。

## 4.7 评价指标及其计算方法

所有指标由 `mirofish/scripts/analyze_formal_results.py` 从原始 `actions.jsonl` 直接计算，脚本与原始数据一并归档，任一指标都可回溯到具体动作记录。

| 指标 | 口径 |
|---|---|
| 逐轮互动量 | 发帖 + 评论 + 转发 + 点赞/点踩；排除 `DO_NOTHING / REFRESH / SEARCH_* / TREND / MUTE` 等非互动动作 |
| **谣言相关互动量** | 被判定为"谣言放大类"的内容数 **+** 指向谣言类内容的互动数 |
| 辟谣相关互动量 | 被判定为"辟谣/求证类"的内容数 **+** 指向官方辟谣类内容的互动数 |
| 互动指向性 | 利用 `LIKE_POST/DISLIKE_POST/LIKE_COMMENT` 动作中记录的被互动对象文本（`post_content`/`comment_content`）判定其指向哪一方的言论 |
| 参与广度 | 产出某类内容的去重 Agent 数 |
| 传播峰值与达峰轮次 | 谣言相关互动量序列的最大值及其所在轮次 |
| 干预窗口指标 | 以注入轮次为界，分别统计干预前、干预后各窗口的累计与均值 |
| 内容立场判定 | 关键词启发式规则（先判辟谣类，再判谣言类，其余为中性）；样例留存于 `content_stance_summary.json` 供人工核验。**局限**：无法识别反讽与引用式否定 |

**明确不予量化的指标**：恐慌强度、囤货倾向、政府信任度、二级传播深度与级联树。前三者在本仿真中不存在可核验的操作化字段；传播树不可重建（`CREATE_COMMENT` 的 `action_args` 不含被评论对象，且转发计数为 0）。这些只能作为定性观察或研究局限列出，**不会以数值形式出现在本章**。

### 4.8.2 实验一：谣言形式的影响

在文本代理设定下，AIGC 高拟真图文谣言（E1B）的谣言相关互动合计为 **25**，低于传统文字谣言（E1A）的 **37**；

## 4.9 组间比较与结果解释

基于 4.8 的真实数据，可以作出的**有限**比较与必须放弃的判断如下。

**可以谨慎陈述的**：
1. 在本仿真设定下，无论介入时点早晚，注入官方辟谣都伴随着更低的谣言相关互动总量。
2. 第 4 小时介入的长尾抑制最彻底（介入后谣言相关互动连续 12 轮为 0）。
3. 各条件的辟谣相关互动合计几乎相同（104–107），说明总讨论体量近似，差异集中在谣言一侧——
   这有助于排除"总互动量差异驱动结论"的混淆。

**不能成立的**：
1. **"介入时点与效果单调"**：第 4 小时介入反而比第 1 小时介入抑制更彻底，说明不能简单断言"越早越好"。
   一个可能的解释是：过早介入时谣言尚未充分扩散，辟谣缺少正在讨论的对象；但这只是单次运行的一种叙事。
2. **任何统计性结论**：每个条件只有 1 次重复，无法估计组内变异，不能使用"显著""稳定证明"等措辞。
3. **实验三的形态差异**：E3B 未运行，无法比较公文式与数智实证式回应。
4. **实验一的方向性结论**：AIGC 文本代理反而更低，与直觉相反，只能作为待验证观察。
5. **现实外推**：本仿真的"小时"未与现实时间校准，所有时点结论都是模型时间单位下的相对比较。

## 4.10 有限的现实合理性验证

本次只做了**形态层面**的合理性检查，没有把仿真曲线与现实曲线逐点对齐：

- **真实侧**（`mirofish/seed/real_timeline.csv`，官方辟谣帖评论的小时级序列）：在首次官方通报
  （2026-08-10 08:35，浦东警方）之后，评论量在随后 1 小时内达到峰值（约 31 条/小时），随后逐步回落。
- **仿真侧**：谣言相关互动在初始注入后的第 1–2 轮达到峰值，随后衰减（见 4.8.3 的逐轮序列）。

两者都呈现"爆发后衰减"的整体形态，这是一个**弱的、方向性**的一致性。
**必须声明**：真实序列的观测对象是"官方辟谣帖下的评论"，而仿真序列的观测对象是"谣言相关互动"，
两者观测对象不同、时间起点不同、指标定义不同，因此**不能**把两条曲线解释为同一现象，
只能用作"模型行为没有出现与常识相悖的单调递增或长平台"这类**最低限度**的合理性佐证。

## 4.11 稳健性分析与不足

1. **重复次数不足**：本次每个条件只有 1 次独立重复，没有进行多重复与敏感性分析。
   因此 4.9 中任何方向性陈述都不具有统计意义。
2. **样本规模**：仅 8 个 Agent，且机构类 Agent 占多数（5/8），公众视角由少数个人 Agent 承担。
3. **平台单一**：只运行在 Reddit 讨论类平台，不做跨平台外推。
4. **转发缺失**：`REPOST` 计数恒为 0，无法观察转发级联，无法重建传播树。
5. **内容立场依赖关键词规则**：已修订剔除弱特征词（避免把质疑官方的表达误判为辟谣），
   但仍可能误判反讽与否定引用；分类样例保留在各运行的 `content_stance_summary.json`。
6. **干预机制为二次开发补丁**：注入时机与内容受控、可核验，但属于对上游代码的定制修改。
7. **LLM 采样不可复现**：即使固定 `random_seed`，模型输出仍有随机性，本研究因此更依赖重复实验
   （本次未能做到）。

## 4.12 治理启示、适用条件与边界

在**本仿真设定下**（8 Agent、Reddit、活跃度被抬升、单次运行），观察到的**条件性差异**是：

1. 有官方辟谣介入的条件，谣言相关互动总量低于无干预基线；
2. 介入时点与效果**不是**单调关系，过早介入未必最优；
3. 介入后谣言相关互动的长尾能否归零，可能比峰值高低更能区分不同介入时点的后果。

这些观察**不构成**对现实政策的效果建议。其成立条件包括：该仿真环境、该 LLM、
该活跃度参数、该 Agent 群体、该内容立场判定规则；任一改变都可能改变结果。
本章只能把以上观察作为"待用更多次独立重复与更大规模 Agent 验证的线索"，
以及为第五章治理机制讨论提供的一种可能的微观行为解释视角。
