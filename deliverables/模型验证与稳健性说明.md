# 模型验证与稳健性说明

> 目的：说明本次仿真**能支持什么结论、不能支持什么结论**，以及为保证可信性做了什么。

## 1. 技术有效性验收（全部实测，非自述）

| # | 验收项 | 方法 | 结果 |
|---|---|---|---|
| 1 | Agent 真实活跃 | 检查 `active_hours`/`activity_level` 与激活判定逻辑 | 修复前：LLM 生成的工作时段与仿真起始小时错配 → 零自主动作。修复后：每轮 6–8 个 Agent 被激活，动作类型齐备（发帖、评论、点赞、点踩） |
| 2 | 真实传播互动 | 检查 `actions.jsonl` 的 `CREATE_COMMENT`/`LIKE_POST` 等 | ✅ 评论、点赞、点踩真实出现；⚠️ 转发 `REPOST` 恒为 0，不据此宣称"转发传播" |
| 3 | 初始状态可控 | 覆写 `initial_posts`，记录被剔除的 LLM 自定义帖 | ✅ 每组的初始谣言帖精确为研究者设定的 4 条；官方辟谣不提前注入（但图谱自带官方 Agent 的自主辟谣行为被允许，已在正文说明） |
| 4 | 干预真正生效 | 以干预文本唯一标记串检索动作日志 | ✅ E2R1 命中第 1 轮，E2R4 命中第 4 轮；"LKX定时事件注入"日志可查 |
| 5 | 指标正确解析 | 用 `round_start/round_end` 还原完整轮次 | ✅ 修正了"16 轮只解析出少数轮"的缺陷 |

## 2. 稳健性

- **独立重复**：每组仅 1 次（预算耗尽）。因此全部结论为**单次运行描述性观察**，不使用统计措辞。
- **敏感性分析**：未开展（需更多次付费运行）。
- **随机性来源**：Python 侧抽样已由 `random_seed` 固定；LLM 采样本身不可复现。
- **干扰源**：DeepSeek 计费延迟入账导致单次运行成本估计存在误差，但不影响数据本身的真实性。

## 3. 已知威胁清单

1. Agent 数量少（8）且机构类占比高 → 传播规模无量级效度。
2. 内容立场为关键词启发式，可能误判反讽/否定引用。
3. 无法重建传播树（评论不含被评论对象、转发为 0）。
4. 干预为运行时补丁，属于对上游代码的定制修改（补丁文件已入库）。
5. 现实对照仅在形态层面，观测对象不同。

## 4. 能成立的结论边界

仅可陈述：**在本仿真设定下，注入官方辟谣的两个条件的谣言相关互动均低于无干预基线，且第 4 小时介入的长尾抑制最彻底**。
不可陈述：统计显著性、现实政策效果、"越早越好"、实验三的形态差异、实验一的方向性结论。
